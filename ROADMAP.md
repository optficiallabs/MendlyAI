# MendlyAI Roadmap

This roadmap describes the planned development direction of MendlyAI.

The roadmap may change based on technical progress, contributor feedback, healthcare requirements, testing results, and open-source community priorities.

## Phase 1 — Repository Foundation

### Target: Initial Release

Planned work:

* complete project documentation;
* add open-source licence;
* add contribution guidelines;
* add security policy;
* add Code of Conduct;
* define repository structure;
* create issue and pull-request templates;
* configure basic continuous integration;
* establish testing conventions;
* publish sample configuration files.

Expected outcome:

A clean and professional open-source repository ready for development and external contribution.

## Phase 2 — Core Clinical Utilities

Planned work:

* clinical data validation;
* structured note utilities;
* workflow validation;
* field consistency checking;
* API request and response validation;
* synthetic healthcare examples;
* reusable validation rules.

Expected outcome:

A first set of practical components that can be used in healthcare software projects.

## Phase 3 — Testing and Quality

Planned work:

* unit testing utilities;
* integration testing examples;
* regression test support;
* edge-case testing;
* invalid-input testing;
* API testing;
* workflow test cases;
* automated quality checks.

Expected outcome:

A reusable testing framework that helps healthcare software teams identify defects earlier.

## Phase 4 — Security and Privacy

Planned work:

* sensitive-data handling checks;
* secure logging utilities;
* access-control validation;
* dependency scanning;
* secret detection;
* configuration review;
* software supply-chain checks;
* security test examples.

Expected outcome:

A stronger development foundation for protecting healthcare information and software workflows.

## Phase 5 — Developer Workflow Support

Planned work:

* pull-request review workflows;
* issue triage support;
* documentation consistency checks;
* release-readiness checks;
* dependency review;
* changelog preparation;
* automated repository checks;
* benchmark framework.

Expected outcome:

A more complete maintainer toolkit for open-source healthcare software development.

## Phase 6 — Codex Integration

Planned work:

* Codex CLI-assisted repository review;
* code-change analysis;
* test preparation workflows;
* issue investigation;
* secure-code review;
* documentation support;
* release validation;
* benchmark evaluation.

Expected outcome:

A practical developer workflow that uses Codex to reduce repetitive maintenance work while keeping developers in control of all changes.

## Phase 7 — Public Benchmark and Evaluation

Planned work:

* create representative healthcare software tasks;
* prepare controlled repositories;
* evaluate code review quality;
* evaluate test usefulness;
* measure false-positive findings;
* measure defect detection;
* measure developer time saved;
* publish reproducible evaluation procedures.

Expected outcome:

Public evidence showing where the toolkit performs well and where improvements are required.

## Phase 8 — Stable Release

Planned work:

* resolve major issues;
* improve documentation;
* stabilise APIs;
* expand examples;
* strengthen automated tests;
* improve installation;
* complete security review;
* publish versioned releases.

Expected outcome:

A stable open-source release suitable for wider developer adoption.

## Long-Term Direction

Future areas may include:

* additional healthcare interoperability support;
* broader clinical API validation;
* more security integrations;
* improved CI/CD workflows;
* container and deployment checks;
* additional benchmark datasets;
* community-developed modules;
* and integrations with commonly used developer platforms.

## Community Participation

The roadmap is open to community feedback.

Contributors can propose new features through GitHub Issues and Discussions.

Major features should be discussed before implementation so that development remains focused, maintainable, and aligned with the project's goals.
